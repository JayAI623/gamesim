# 方法论

**三行摘要**
1. 框架是「主体 → 效用（收益卡）→ 显式期望收益选行动 → GM 裁决 + BDM 基线」，每个角色都是一次独立的 `claude -p` 调用，信息隔离靠 prompt 拼装。
2. 开跑前要过三道关：显示偏好法反推效用（带样本外检验）、5 视角独立审查 + 反驳式核实、一屏对齐页给用户确认。
3. 推演结果是条件情景的分布，不是预测；最常见的失真来自输入写错（红线、形状、折现）和 LLM 的合作偏差，见「踩过的坑」。

---

## 1. 流程

```
情报（intel.md）──► 主体与共享变量 ──► 每方一个研究员（utility_research.md，显示偏好）
                                              │
                                              ▼
                 5 视角审查 + 1 核实人（review.md） ──► gamesim check（模式化检查）
                                              │
                                              ▼
                      对齐页（alignment.md）✋ 用户确认
                                              │
                                              ▼
       BDM 基线（gamesim bdm） ──► 逐轮推演 × N 局（gamesim run，可带 swap.json 分支）
                                              │
                         ┌────────────────────┼─────────────────────┐
                         ▼                    ▼                     ▼
           压力测试（gamesim fork）   度量（aggregate / compare）   第二层（gamesim score / sweep）
                         └────────────────────┴─────────────────────┘
                                              ▼
                                          report.md
```

## 2. 步骤

### 步骤 0：情景输入
- **手动**：用户给的材料原样写进 `scenario.md`，缺的在步骤 1 补齐。
- **搜索**：用 `prompts/pipeline/intel.md` 派情报员，返回的简报写进 `scenario.md`。
- **混合**：用户材料放进 `user_notes`，再走搜索。

### 步骤 1：主体与共享状态变量
- 保留 **3–6 个有效玩家**，其余并入 `background` 或 `exogenous`。`weight`（影响力份额）总和为 1。
- 共享状态变量 3–10 个，每个写清 0 端和 100 端的含义、当前值和口径（`variables[].source`）。效用只能定义在这些变量上。
- 默认行动阶梯（地缘政治）：0 让步 / 1 维持现状 / 2 公开表态 / 3 谈判 / 4 联盟动员 / 5 经济施压 / 6 信息战或代理人 / 7 军事示威 / 8 有限打击 / 9 大规模冲突 / 10 全面战争。商业或社会场景要改写成对应的阶梯。

### 步骤 2：每方一个研究员反推效用（显示偏好）
- 用 `prompts/pipeline/utility_research.md`（引擎里同名模板可用 `gamesim.templates.render` 渲染）。
- 找 8–12 个历史决策点，要求是它**被迫在两个目标之间取舍**的时刻；只信行动，不信表态。
- **拟合 / 检验分割**：`fit_before` 之前的决策拟合权重，之后的 2–4 个留作样本外检验；没命中就如实写，不回头改权重。命中率写进 `oos_hit_rate`。
- 归纳基准率（`base_rates`，写成 a/b），样本少于 3 要注明；0/n 和 n/n 不能当点估计，用 Wilson 区间的上沿做 cap。
- 形式：`U = Σ w_k · u_k(x_k)`，`u_k ∈ [−1, +1]`，形状 linear / concave / convex / threshold / peak，权重和为 1。

### 步骤 3：独立审查 ✋
- `prompts/pipeline/review.md`：地缘政治、政治学、博弈论、数学与概率、数据分析 5 个审查人并行，彼此独立，只看输入不看结果。
- 1 个核实人去重，对高、中严重度的条目做**反驳式核实**（默认不成立，有证据才保留）。
- 能机械检查的先跑 `gamesim check entities.json`：第 0 轮红线、`-`+convex、按年轮次缺 `delta`、样本外命中率低。

### 步骤 4：对齐页 ✋
用 `prompts/pipeline/alignment.md`，一屏：情景 3 行、变量表、每方一行效用公式 + BDM 四参数、拿不准的 1–3 条、审查统计、盲点一行。**停下来等用户回复**。

### 步骤 5：BDM 基线
`gamesim bdm <run>/entities.json -o <run>/bdm_result.json --md <run>/bdm_result.md`。BDM 是单议题、完全信息的简化模型，只当基线：报告中位和加权均值落点，和 LLM 推演的落点对照。

### 步骤 6：逐轮推演
`gamesim run <base> --entities entities.json --runs 3 [--swap swap.json]`。每轮：
1. **prep**：按 seed 预先掷好骰子，写每方的 prompt（收益卡、私有信息与日记、公开局势、收件箱、行动菜单、本轮注入的事件）。
2. **各方同时出手**：每方一次 `claude -p`，输出 JSON，必须含 `options_considered`、`chosen_index`、`chosen.escalation`、`position_now`。校验失败带着错误重试，原始输出落盘 `raw_<code>_<i>.txt`；重试用完记为「维持现状/观望」（escalation 1，`fallback: true`）。
3. **GM 裁决**：
   - **盲骰**（`blind_dice`）：GM 第一阶段只承诺各行动和外生事件的概率 `p_gm`，看不到骰子；脚本按预掷的骰子判成败；第二阶段 GM 只描述后果、更新状态变量，不得改成败。
   - **基准率上限**（`base_rate_cap`）：偏离自身历史基准率的行动，概率不得高于基准率，除非写出本轮的新事实。
   - **参照类**（`reference_class`）：给 `p_target` 前先写参照类和基准率，再说本轮证据怎么调，附 90% 区间。
   - **折现**（`discount`）：收益 k 个月后兑现要乘 δ^k。δ 是**月**因子，按年的轮次要在每个实体上写 `delta`。
4. **apply**：写 `rounds/round_NN.json` → `state.json` → `private/*` → `turns/rNN/commit.json`（原子写，可幂等重放）。

### 步骤 7：度量与报告
- `gamesim aggregate <base>`：目标命中 k/n 和 Wilson 95% 区间；未跑完的局不登记预测。
- `python -m gamesim.compare <run>`：每轮升级强度、LLM 立场 vs BDM、理性一致性审计（是否选了 EU 最高项、EU 算术错误数）。
- `gamesim status <base>`：每局的下一步，以及兜底和原始失败输出的计数（拒答统计，见坑⑨）。
- 报告：一句话回答（≤30 字，附信心和依据）→ 轨迹表 → 均衡判断 → LLM vs BDM → 可信度审计 → 盲点一行 → 附录。

## 3. 两层结构（第二层：策略臂打分）

有些问题里真正关心的决策者（一个家庭、一家小公司、一个投资者）动不了共享变量，其他玩家也不会回应它：它面对的是**对自然的决策问题**，放进同一局推演既没有策略互动，也识别不出「最优」。做法是拆两层：

- **第一层**：只有能动共享变量的机构玩家，跑 N 局，得到状态轨迹和 GM 写的「影响栏」。
- **第二层**（`gamesim score strategy.json <base>`）：每个决策者固定若干策略臂（从第 1 轮执行到底，不中途换臂）。每条轨迹 × 每个决策者调一次打分员，只给 F 的分项（共享变量覆盖不到的私有结果，如收入、家庭团聚）；其余由代码算：
  `U = Σ w · 暴露系数[变量][臂] · u(变量)`，F 也是其中一项；红线（可限定在某些臂上）触发当轮 U = −10；按轮折现后累加，按局权重加权排名。
- 敏感性：暴露系数和关键分项 ±30%，标出前两名翻转的情形。
- 分项拆解：平均 F、各分项、U 中非 F 的部分，用来识别「领先是从哪来的」（坑⑦）。
- 翻转点：`gamesim sweep … --run run_4 --from-round 4 --set S=56,70,80,90,96`，从某轮起覆盖状态变量，看第一名在哪个值翻转。

## 4. 分支与压力测试

- **分支**（`swap.json`）：`after_round` 轮结算后，按 `assign`（分层分配）或 `p`（种子化抽签）给每局选一个分支，用 JSON-Patch（`gamesim.conditions.apply_patch`）改 `entities.json`（如换某一方的效用权重），并把分支的公开事件在下一轮开头注入。原文件保存在 `entities.pre_swap.json`。汇总权重 = `p[分支] / 该分支的局数`。
- **压力测试**（`gamesim fork <base>/run_3 <base>/run_4 --upto 2 --events stress.json`）：复制某局的前 N 轮（同一 seed，后续骰子相同），在第 N+1 轮注入事件后继续推。源局在该轮已有的用户事件（比如分支公告）会保留。fork 出来的局带 `fork.json`，默认不进第一层汇总和第二层打分，要用 `--runs` 显式指定。

## 5. 跨局一致性规则

同一个话题跑过多局时，结论不一致常常是输入不一致造成的。

- **A 背景方借用先验**：某方在这一局只是背景、在另一局是独立玩家时，以另一局的结果为准。维护一张先验登记表（每条写来源局和样本数），把用得上的条目复制进 `entities.json` 的 `exogenous_priors`；GM 给这些事件的概率不得超过上沿，除非写出新事实。
- **B 统一事实快照**：每局从最新的事实快照起步；情报员只做增量更新，写成新日期的快照，并列出「已知冲突」表（旧值、现值、依据）。`scenario.md` 写明基于哪份快照。
- **C 统一结果词典**：结果的 key 和定义只在一个词典文件里定义一次（模板见 `prompts/pipeline/outcomes.md`），GM 的 `p_outcomes` 和报告只用这里的 key；`@日期` 表示日历时间窗，跨局比较时时间窗必须一致。

## 6. 踩过的坑

| # | 坑（一句话） | 怎么防 |
|---|---|---|
| ① | 把「到阈值就做某事」的行为规则写成红线，一局 8 方里 6 方第 0 轮就 U = −10，所有选项没有差别，最该出现的应对（入籍、离开）反而没有激励。 | 红线只放灾难点（越过即不可接受）；行为规则放 `soft_rules`（渲染成「行为规则」，不计惩罚）。`gamesim check` 会报第 0 轮已突破的红线。 |
| ② | `direction: "-"` 配 `convex` 和直觉相反：引擎先算 z = 1 − z 再平方，变量越大边际损失**越小**（S 从 45→60→80→95，Δu 为 −0.285、−0.24、−0.075）。 | 想表达「越接近阈值损失越大」用 `concave`（同一例子 Δu 为 −0.218、−0.371、−0.447）。`gamesim check` 和 `strategy.validate` 都会提醒。 |
| ③ | 折现因子按**月**：默认 short 0.8、long 0.95，每轮 1 年时一年后只剩 0.8¹² ≈ 0.07，5 年后 0.95⁶⁰ ≈ 0.05，长期布局的收益在 EU 里约等于 0。 | 年度轮次在每个实体上显式写 `delta`（月因子，如 0.99 ≈ 年化 0.89）；第二层写 `discount_per_round`（按轮的因子）。 |
| ④ | LLM 玩家偏温和、偏合作：平稳局里最高升级常只到 4，冲突变量很少越过危机线。 | 坏情况不要等它自然出现，用 `gamesim fork` 注入冲击做压力测试；报告里写明最高升级和合作偏差的可能。 |
| ⑤ | 分支事件（如大选，p = 0.6）样本少时随机抽：3 局全落同一分支的概率 0.6³ + 0.4³ ≈ 0.28，另一分支整个缺席。 | 用 `swap.json` 的 `assign` 分层分配（如 D、D、R），汇总按 `p[分支] / 局数` 加权（0.3/0.3/0.4）。 |
| ⑥ | GM 会把注入的冲击在期末状态里回落：一次危机中冲突烈度一度到 75，年末状态只记 66。 | 按年轮次时在报告里说清状态变量是**期末值**；需要峰值时在注入事件里要求 GM 写出期间峰值，或缩短每轮时长。 |
| ⑦ | 第二层「期权」类策略（如保留第三地身份）在不扣维持成本时被公式抬高：两个臂的 F 几乎相同（89.4 vs 89.4），领先完全来自期权的暴露系数。 | 看 `summary.md` 的分项拆解（平均 F、非 F 部分）；把维持成本写进 F 分项或臂的描述；差距在假设误差内时报告写「两者持平」。 |
| ⑧ | 样本外命中率低（如 1.5/4）的效用函数照样进推演，读者会以为它和别的方一样可靠。 | 在对齐页的「拿不准」里标出来；`gamesim check` 对命中率 < 50% 的实体给提醒。 |
| ⑨ | 模型拒答（例如要求以真实政府第一人称写军事方案）会被兜底成「观望」（escalation 1），系统性地把局势推向缓和。 | 每次失败的原始输出都落盘为 `raw_*.txt`，`gamesim status` 统计每方的兜底次数；兜底多的一方要改写 prompt（第三人称、匿名 codename）或单独标注。 |

## 7. 审查发现了什么（案例）

一局「在美华人」推演（5 个机构 + 3 类家庭）开跑前，5 视角共报 50 条，核实后采纳 33、驳回 11，其中 4 条涉及问题定义、交给用户定。最有价值的几条：

| 编号 | 发现 | 怎么核实的 | 改法 |
|---|---|---|---|
| R1/R2 | 红线写成了行为规则 | 用原文件算 U，第 0 轮 6/8 方 = −10；改完重算 8/8 正常 | 只留灾难点，其余移进 `soft_rules`（坑①） |
| R3 | 目标事件（集体性措施 S≥80）恰好是美方自己的红线，概率被结构性压到 0 | 对照判例和 2025 年对他国用过两次的事实 | 红线改成只管针对公民的措施（S≥90），S 改成分段锚点表 |
| R5 | 5 个「越高越糟」的项写成 `-` + convex，方向和备注相反 | 逐段算 Δu | 改 concave（坑②） |
| R6 | 每轮 1 年却用月折现因子 | 0.8¹² ≈ 0.07 | 每个实体写 `delta`（坑③） |
| R7 | 家庭福祉 F 没有更新口径，又和共享变量重复计算 | 两位审查人对 F 权重的提案方向相反，根因是 F 没公式 | F 只装私有分项，写成公式 |
| R8 | 家庭面对的是对自然的决策，同场推演识别不出「最优」 | 家庭的影响力约为机构的 1/30，其他方效用里家庭项权重 0–0.05 | 拆成两层（第 3 节），由用户确认 |
| R9 | 大选时点落在错误的轮次，换党权重写在私有信息里 | 对照就任日期 | 公开事件 + 第 2 轮后分支换权重（第 4 节） |

被驳回的典型：没有来源的系数（如「能力 = 60 + (C − 85) × 0.8」，与效用里的 C 双重计入）、只改噪声以内的权重、本轮没核实的数字。

## 8. 成本与限制

- 调用次数 ≈ 局数 × 轮数 × (实体数 + GM 次数)，盲骰时 GM 每轮 2 次。5 方 × 6 轮 × 3 局 ≈ 126 次，外加第二层每条轨迹 × 每个决策者 1 次。
- 信息隔离靠 prompt 拼装：私有信息只内联进对应实体的 prompt，`claude -p` 不开任何工具、cwd 是空临时目录；这不是密码学意义的隔离。
- 3 局的任何频率区间都很宽（0/3 的 Wilson 95% 区间是 0–56%）。
- 效用权重、暴露系数、F 公式都是人定或研究员推出来的假设；报告里要写明哪些是推出来的、敏感性做到了什么程度。
